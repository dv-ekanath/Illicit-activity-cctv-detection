# VPA Decisions, fallbacks and TODOs

Format: **decision** - alternatives - reason.

## Environment / repo
- **Use the existing git repo at `illicit_detection/` and commit locally there** - the parent folder is not a repo. Commits are local only, nothing pushed.
- **Un-ignore `docs/vpa_samples/**` and `notebooks/` in `.gitignore`** - `*.png` is globally ignored, which would silently drop the deliverable images. Alternative: `git add -f` per file; rejected as fragile.
- **PyAV instead of ffprobe/ffmpeg for S1/S2** - no ffprobe binary on this machine; PyAV (bundled FFmpeg libs) exposes the same stream metadata and per-frame picture types and is the plan's named decoder option.
- **Clips are written to `data/processed/clips_vpa/` (sample runs: `clips_vpa_sample/`)** - never into the legacy `clips/` path, so nothing existing is overwritten.
- **`backend/` does not exist in this checkout** - nothing to edit; the shared brightness function `vpa.common.mean_luma/is_dark` is what `backend/utils.py` and `infer_zerodce.py` should call later.

## S1 - profiling
- **S1 profiles all 300 videos, not just the sample set** - the sample set and the data-driven thresholds are *derived from* S1 statistics, so S1 must see the whole dataset. It is metadata/statistics only (480 s with 8 workers), no clips are extracted. Cached at `outputs/vpa_cache/profiles.json`.
- **Dark threshold = 50 (mean luma Y)** - rule: the luma below which the darkest 5 % of all frames fall (measured 48.5 -> rounded to 5 -> 50; 4.8 % of frames are < 50). Alternative: Otsu split of the pooled luma histogram gave 76, which would enhance 37 % of all frames (the distribution is broad and unimodal, so a split rule is unreliable). 50 equals the old `extract_clips.py` value; `infer_zerodce.py`'s 80 and the backend's HSV-V check should move to `vpa.common.is_dark` with this value later (backend not edited today).
- **Blur floor** - 5th percentile of per-video median Laplacian variance = 269 (10th: 413). The S8 quality gate uses a clip-level floor set from this (see S8 entry).
- **DOVER / FAST-VQA: TODO (not done)** - neither ships in pip with weights (pyiqa 0.1.16 has no DOVER/FAST-VQA entry; the official repos need manual weight downloads). Classical stats (Laplacian variance, Immerkaer noise, blockiness, contrast) are used instead; `profile.vqa` in config is a placeholder.
- **Sample-set selection rule** (seed 42, `profile.select_sample_set`): eligible = 20 s <= duration <= 300 s; very-dark = lowest median luma; overlay = highest S3 overlay score among non-dark; shot-cut = strongest cut candidate whose 12-FPS S3 detection confirms 1-8 cuts; moving-camera = highest phase-correlation motion fraction (>= 0.35); each class = video nearest to the class median brightness/sharpness *with temporal GT* whose event lies inside the analysed window (Normal: no GT needed). Roles never share a video. Alternatives: random pick (not representative), hand pick (not reproducible).
- **Moving-camera videos: 2 of 300 (0.7 %)** - far below the 5 % `s5_min_video_fraction`; see S5 entry.
- **Letterbox bars appear in 206/300 videos and an overlay/caption blob in 218/300** (detector is permissive; see S3 notes).

## S2 - resampling
- **PyAV, nearest-timestamp rule** (output frame k = source frame with pts nearest to k/12 s, ffmpeg `fps`-filter behaviour) - alternative decord (not installed, no benefit). Verified: for 30 FPS sources the picked source-frame gaps alternate 2,3,2,3 (exactly 12.00 FPS, max timing error 16.7 ms). The OLD rule is `step = round(30/12) = round(2.5) = 2` (Python rounds half to even) = **15 FPS**; it only 'works' by accident of float rounding (a source reporting 30.000000000000107 FPS would get step 3 = 10 FPS), another reason for timestamp-based picking.
- **Analysis cap**: sample runs analyse at most `general.sample_max_seconds` = 300 s per video (all eight sample videos are shorter, so nothing is truncated); full runs have no cap.

## S3 - structural cleaning
- **Shot cuts: classical HSV-histogram + edge-change-ratio detector, written here** (plot needs the raw signals); PySceneDetect ContentDetector is run as a cross-check and recorded in metrics. **TransNetV2: TODO** (not attempted yet; classical version meets the plan's S3 requirement).
- **Frozen/black frames**: frozen = mean |gray diff| < 0.05 for runs of >= 4 frames at 12 FPS; black = mean luma < 10 and std < 8. Many UCF-Crime videos are frame-duplicated at 30 FPS (20 % "identical" frames natively) but the 12-FPS resampling mostly removes this.
- **Letterbox**: flat-black row/column profile (mean < 22, std < 9, contiguous from the border), +2 px safety margin, max 35 % per side. It also correctly crops 'picture-in-picture' videos (Vandalism032 has black bars on all four sides). Detected bars in 206/300 videos.
- **Overlay/timestamp**: classical detector = per-pixel frequency (over 40 sampled frames) of thin near-saturated strokes (top-hat > 40 & luma >= 185, or black-hat > 40 & luma <= 70), merged horizontally, kept only if text-like (aspect >= 2.5, w >= 20, 5..36 px high, density 0.07-0.7) and in the outer 14 % border band; strokes inside the region are inpainted with Telea. Tuned by eye on 8 videos: timestamps, captions and logos found; some textured-static borders (shelves, signs) produce false positives (218/300 videos flagged), harmless but they inpaint a little real content. **EAST / PaddleOCR text detector: TODO** (would raise precision).
- **Order inside S3**: letterbox crop -> overlay removal -> shot cuts -> frozen/black (all on 12-FPS frames).
- The X3 sample (existing Zero-DCE++ path) shows a blue/purple colour cast on monochrome IR frames - this is the existing stage-2 model's behaviour on grayscale input, not a bug in the pipeline; S4 keeps monochrome sources monochrome (decision logged there).

## S6 - motion analysis
- **Flow = Farneback on all frames, RAFT-small (torchvision, pretrained, no training) on ~13 pairs per sample video** for the side-by-side and an agreement number (`raft_vs_farneback_corr` in metrics). RAFT on every frame would roughly double the run time for no downstream use. **NeuFlow v2 / SEA-RAFT: not used** (RAFT-small meets the 'modern' requirement and ships in torchvision).
- **Flow is measured against the last *distinct* frame and divided by the elapsed 12-FPS steps.** Reason (found in the first S6 run): many UCF-Crime videos are 10-15 unique FPS stored at 30 FPS, so resampling to 12 FPS sometimes picks the same picture twice, which made the motion-energy signal a 0/high sawtooth. Isolated duplicates now hold the previous value; runs of >2 duplicates (static/frozen) give 0.
- **Motion energy = mean flow magnitude over all pixels (px per 12-FPS step)**, not per moving pixel, so a large moving crowd scores higher than one small mover. Companion signals: foreground ratio, blob count, direction entropy (16 bins, magnitude-weighted), mean |divergence|, mean |curl|.
- **Global-change guard**: foreground ratio > 0.55 marks a frame as an illumination change / scene swap (fades, flashes; e.g. Fighting018 has a fade at 41 s that gave flow 11 px), and S8 ignores those frames together with the S3 frozen/black/cut-neighbour frames (`clean.bad_frame_mask`).
- **MOG2 shadow handling**: MOG2's built-in shadow flag is OFF; the HSV rule from the plan (V ratio 0.45-0.95, |dS| <= 40, |dH| <= 12) is applied against MOG2's background image, so the step is explicit and visible.
- **Showcase frame for samples**: peak smoothed motion energy among valid frames, restricted to the ground-truth event window when one exists (so the sample shows the action, not a title card or a lighting change). The stage images are produced by re-running S6 on a 90-frame window around it.
- **Observation (moving-camera video Normal_Videos_913)**: MOG2 marks most of the frame as foreground when the camera pans; this is exactly the failure S5 would fix (see S5 entry).

## S4 - photometric enhancement
- **One brightness measure**: `common.mean_luma` (gray = BT.601 luma Y) < `enhance.dark_threshold` = 50 (S1-derived). The per-frame decision is median-filtered (9 frames) with hysteresis (+5) and ignores black frames (luma < 10, e.g. fades). `backend/utils.py` does not exist in this checkout and `infer_zerodce.py` (default 80) was not edited (out of scope: `src/inference` is used by the live system); both should call `vpa.common.is_dark` later.
- **Zero-DCE++ at native resolution (e.g. 320x208), not 256x256 -> 640x640 stretch**; it is fully convolutional. The network is imported read-only from `src/training/zerodce_model.py` (no retraining, `stage2_best.pth`).
- **Deflicker, two layers**: (1) the 24 curve-parameter maps are EMA-smoothed over time (alpha 0.6, reset at shot cuts / run starts), (2) the mean luma of the enhanced run is smoothed by a zero-phase (forward+backward) EMA of log-luma and each frame is gamma-mapped to it (bisection, gain limit 1.35). Order: Zero-DCE++ -> denoise -> deflicker.
- **Temporal denoise: FastDVDnet (pretrained, MIT licence) is the default**; its definition and weights are downloaded on first use into `models/fastdvdnet/` (git-ignored, not vendored). Noise level for its noise map is estimated per run (Immerkaer, clamped 5..55). If the download/import fails the code falls back to `cv2.fastNlMeansDenoisingColoredMulti` (implemented, `enhance.denoise.method: classical`).
- **Monochrome sources stay monochrome** (`enhance.keep_mono`): on IR/gray footage the stage-2 Zero-DCE++ weights add a blue/purple cast (visible in the X3 sample); the enhanced frame is converted back to luma when the source saturation is ~0. Colour sources still show a mild cast from the existing model (not changed, no retraining today).
- **Comparison demo on non-dark videos uses SIMULATED low light** (gain 0.5, gamma 1.6, sigma-2.5 noise) and is labelled as such in every title/metrics file, because forcing Zero-DCE++ on bright footage is not representative; real dark runs are used when >= 10 % of the video is dark (only Vandalism032 here). The reference row 'original bright frames' is included for those.
- **Metrics**: NIQE / BRISQUE via pyiqa (lower is better), flicker index = mean |delta frame brightness|, noise sigma, YOLO persons per frame (recall proxy; no ground truth on UCF-Crime). Observed on the sample set: Zero-DCE++ raises noise sigma (e.g. 2.7 -> 10.2) and the temporal denoise brings it back (6.2); NIQE favours the full chain over Zero-DCE++ alone in 7/8 demo windows, noise sigma drops in 8/8, the flicker index improves in 5/8 (already tiny in static dark scenes) - BRISQUE is reported but is mixed; CLAHE (baseline only) amplifies noise most.

## S7 - actor analysis
- **Detector = COCO `models/yolov11/yolo11s.pt`, not the fine-tuned `best.pt`** (plan allowed this fallback; no training either way). Evidence (`S7_detector_check`, 64 sampled frames over the 8 sample videos): 34 % of the fine-tuned model's boxes cover > 35 % of the frame (a standing person never does) and only 14 % of them are also found by COCO, versus 0 % implausible boxes for COCO; visually the fine-tuned boxes are shelf-sized rectangles on UCF-Crime store/street footage (domain shift from night-time LLVIP/ExDARK). Rule coded in `actors.select_detector`: COCO if the fine-tuned boxes are confirmed >10 points less often by the other model or >15 % are implausible; the choice is persisted in `outputs/vpa_cache/detector_choice.json` and re-run with `--reselect-detector`. **TODO for the report:** the fine-tuned detector was not wrong on its own domain (mAP50 0.907 on LLVIP) - it just does not transfer to these frames.
- **Tracker = ultralytics `BYTETracker` driven directly** with the detector's per-frame boxes (so the tracker state is reset per video and detections can be batched), `frame_rate=12`, thresholds in config. Detection runs at conf 0.1 (ByteTrack second association) and tracks need >= 0.25 to start.
- **Interaction signals** per frame: people count (tracked), min centre distance between two people in *person heights* (scale-invariant, 9 = none), max IoU, speed in person-heights per 12-FPS step, and `interaction = proximity * (0.4 + 0.6*speed)` for >= 2 people (0.5*speed for one person). The weights are hand-set design choices, tuned only by looking at the samples (no labels).
- **Actor crop**: union box of the interacting cluster (people closer than 1.6 person-heights; all people if nobody interacts) + 25 % margin each side, expanded to a square (min 96 px, capped by the frame), zero-phase EMA smoothing of centre/size (jitter drops 2-3x, see metrics), slid inside the frame, then letterboxed and resized to 224 with INTER_AREA; whole frame when nobody is detected (smoothing blends in/out). On 320x240 frames a square window taller than the frame is clipped to the frame and letterboxed.
- **Pose estimation: skipped** (optional in the plan; everything else came first; revisit only if an ablation asks for it).

## S8 - temporal analytics and clip selection
- **Activity score** = 0.45 * motion energy + 0.15 * foreground ratio + 0.40 * interaction score (each clipped to [0,1] by `motion_ref` 0.8 px/step, `fg_ref` 0.10); frames flagged by S3 (frozen, black, +-2 around a cut) or by S6 (global change) are set to 0; Savitzky-Golay (25 frames, order 3) smoothing. The reference values were read off the p90 of motion/foreground inside the three annotated sample videos; they are config values, not trained, but **they were tuned on three videos only** - treat tIoU numbers as indicative.
- **Proposals** = hysteresis (high 0.25 / low 0.15) + peak check (prominence 0.08), merge gaps < 2 s, drop < 2 s, pad 1 s. If an abnormal video yields nothing the top-3 highest-activity windows are used (`proposal_method: fallback_rank`) so every abnormal video still gets clips.
- **Ground truth**: `annotations/Temporal_Anomaly_Annotation_for_Testing_Videos.txt` (frames at 30 FPS -> seconds). Sample-set tIoU: Robbery137 0.96 (event covers 83 % of the video), Fighting018 0.35 (recall 1.0, precision 0.35: the video has an animated title card and other movement outside the 2.6-14 s fight), Vandalism017 0.15 (recall 1.0, two 2-s events inside lots of other movement). Motion/interaction activity is not the same as 'crime', so precision is limited by design; the proposals bias sampling towards action rather than detect the crime.
- **Clip geometry**: 16 frames, stride 4 at 12 FPS = 61-frame span (5.08 s; the legacy 'MIN_FRAMES_NEEDED = 64' padded the last frame, new clips never pad). Abnormal clips: candidates whose centre lies inside a proposal, never across a shot cut, spread over the proposals by farthest-point sampling (min start separation 16 frames, +-3 frames jitter, seeded per video). Normal: uniform + 25 % highest-activity windows as hard negatives (quota is kept when the cap truncates). 1.5x oversampling before the gate/dedup, then the highest-priority `clips_per_video` (train 16 / test 8, unchanged) are kept.
- **Quality gate** (replaces `std > 0.01`): frozen (> 50 % identical frames), black (mean luma < 10 or > 20 % black frames), blurry (mean Laplacian variance < 130 = half of the S1 5th percentile 269), abnormal-class clip with mean motion < 0.08 px/step, spans a shot cut, > 20 % illumination-change frames. The legacy std check is kept in the code (`old_valid`) for the old-vs-new comparison (X5): on Fighting018 it accepts a frozen title card and low-motion clips that the new gate rejects.
- **Deduplication unchanged** (cosine > 0.99 of mean-abs-frame-diff fingerprints) but now also returns the similarity matrix; it drops 0 clips on the sample set (max similarity 0.98) because clips are already spread out.
- **Ordering fix found on the sample**: truncating to the per-video cap in time order dropped the high-activity end of Normal videos, so candidates are ranked by priority and only the final storage is time-ordered.

## S9 - packaging
- **uint8 clips**, `(16,224,224,3)` RGB as in the plan (4x smaller: 2.4 MB vs 9.6 MB per clip), JSON sidecar next to each clip. **`src/training/videomae_dataset.py` does `torch.from_numpy(np.load(p)).float()` without /255, i.e. it expects float32 in [0,1]. Training on these clips needs `raw.astype(np.float32)/255` in the loader (one line; training code was not touched today), or run extraction with `--clip-dtype float32`.**
- Output dirs are `clips_vpa/` (full) and `clips_vpa_sample/` (sample); layout `fold_N/{train,test}/<Label>/scene/<stem>_cNNNN.{npy,json}` mirrors the old one.
- The sample videos are all in the *train* split of fold 1 (the 3 annotated ones are UCF 'testing' videos, but the Action_Recognition split is independent of that).
- **Dataset analytics report** `_vpa_report/{report.json,report.md}` next to the clips + `S9_dataset_report` sample plot.

## S3 update - TransNetV2 added (was a TODO)
- `transnetv2-pytorch` (MIT; the pretrained weights ship inside the pip wheel, installed with `--no-deps`) works, so the shot detector is now **`clean.shot_cut.method: both` = union of the classical HSV+ECR detector and TransNetV2** (probability > 0.5, cuts within 3 frames merged). On the sample set TransNetV2 found the same cuts as the classical detector plus a few extra (e.g. Normal_Videos_722: classical 2, TransNetV2 5); extra cuts only make clips more conservative (a clip may not span any cut).
- **TransNetV2 runs on CPU**: on this RTX 5060 / torch 2.12 nightly its Conv3D forward failed on CUDA (kernel/dispatch error), the CPU path takes ~3.5 ms/frame (12 s for a 290 s video). TODO: retry on GPU with a stable torch build.
- Remaining TODOs for S3: **EAST / PaddleOCR text detector** (the classical stroke-frequency detector is used; raises false positives on textured borders).

## S5 - camera-motion compensation: **skipped** (decision, not an omission)
- S1 measured camera motion with phase correlation between frames 0.1 s apart (>= 1.5 px in >= 35 % of the sampled pairs): **2 of 300 videos (0.67 %)**, far below `profile.s5_min_video_fraction` = 5 %. Following the task rule ('only if S1 finds a meaningful number of moving-camera videos') S5 is not implemented; `camera:` in config.yaml is a placeholder. The sample set still contains one of the two (`Normal_Videos_913`) and its S6 sample shows the consequence (MOG2 foreground ratio ~0.17, flow 1.5 px/step, i.e. the whole frame 'moves'); the S8 gate would not catch this because the clip has plenty of motion. If these two videos matter, add ORB+RANSAC homography warping before S6 (about 60 lines) or simply exclude them (`cam_moving_frac >= 0.35` in `outputs/vpa_cache/profiles.json`).
